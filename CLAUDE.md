## What This Is
A **React + TypeScript + Vite** web app that helps household members track food expiry dates, reducing waste. Users can add items with expiry dates, get status indicators (fresh / expiring soon / expired), edit items, and delete them. Authentication is handled via Supabase Auth.

  storage_location storage_location NOT NULL,  -- Fridge|Freezer|Pantry

## Key Components

### `Auth.tsx`
- Toggle between Sign In / Sign Up
- Uses `supabase.auth.signInWithPassword` and `supabase.auth.signUp`
- Shows confirmation message after sign-up (email verification is confirmed ON in the Supabase project as of 18/8/26)
- Password field has a show/hide toggle (added Feedback Sprint UI feedback pass two, 21/8/26) — a plain-SVG eye/eye-slash icon button inset in the field, flipping the input's `type` between `password`/`text`; `aria-label`/`title` flip between "Show password"/"Hide password" too

### `useItems.ts` (`src/hooks/`)
- Owns all Supabase reads/writes for `items` — `AddItemForm` and `ItemList` no longer talk to Supabase directly
- Returns `{ items, loading, error, addItem, updateItem, deleteItem, refetch }`
- `FoodCategory` — 12 values as of Feedback Sprint 2 (22/8/26): the original 11 plus `'Microwave Meals'` (added as `'Frozen Meals'`, renamed same sprint — see `decisions.md`)

### `validateItem.ts` (`src/lib/`)
- `validateItemForm(values)` — shared client-side validation used by both the add form and the inline edit form
- `todayLocal()` (Feedback Sprint 2, 22/8/26) — today's date as a local `YYYY-MM-DD` string, replacing `new Date().toISOString().slice(0, 10)` (which reads the UTC calendar date) everywhere "today" is needed for a date-only field; fixes a false "date must not be in the future" error that showed up for part of every day in any UTC+ timezone
- `checkStorageSafety(values)` (Feedback Sprint 2, 22/8/26) — thin wrapper around `getAdjustedExpiry`, returns the warning message if the category/storage/opened combination is unsafe or `null` if it's fine; called by both `AddItemForm` and `useItemDetail.saveEdit` so an unsafe combination is blocked at save time instead of just warned about afterward

### `AddItemForm.tsx`
- Props: `onAdd: (input: ItemInput) => Promise<{ error?: string }>`
- Collects all required fields: name, category, storage location, printed expiry date, quantity, opened status, date opened (conditionally) — every field has its own visible `field-label` title
- No longer rendered inline on the dashboard (Slice 4 fifth revision) — `App.tsx` opens it inside `AnimatedModal` from a fixed "+" button
- Category auto-guessed from the name as it's typed (`guessCategory`, Slice 6) until the user picks one themselves, tracked via a `categoryTouched` flag; date field defaults to today instead of blank (Slice 6), still fully editable
- **"Opened?" is one label-plus-checkbox row (Feedback Sprint 2, 22/8/26)** — `.opened-toggle` replaces the previous stacked layout; the date-opened field only appears once the checkbox is checked, and unchecking it clears whatever date was entered
- **Blocks an unsafe save instead of warning and allowing it (Feedback Sprint 2, 22/8/26)** — `checkStorageSafety` (`validateItem.ts`) runs right after the existing form validation; if it returns a message, the item is not saved and the message is shown as the form error

### `useAnimatedModal.ts` / `AnimatedModal.tsx`
- Shared open/visible/origin state machine + portal/backdrop/escape/scroll-lock shell, extracted once the add-item flow needed the same "grows from where you clicked" animation as the item-detail modal
- `useAnimatedModal()` returns `{ open, visible, origin, openFrom, close }`; `openFrom(sourceEl)` captures `sourceEl.getBoundingClientRect()` as the animation's origin point
- Used by both `App.tsx` (add-item modal) and `ItemList.tsx` (item-detail modal)

### `adjustedExpiry.ts` (`src/lib/`)
- `getAdjustedExpiry(item)` — pure function implementing the full Adjusted Expiry Date Algorithm (`decisions.md`) for all 12 categories (as of Feedback Sprint 2), returns `{ safe: true, adjustedDate }` or `{ safe: false, message }` for unsafe/not-recommended combinations
- `getDaysRemaining(adjustedDate)`, `getExpiryStatus(days)` — derive the Fresh/Soon/Expired status from the adjusted date, not the printed one
- **`evalMicrowaveMeals` (Feedback Sprint 2, 22/8/26; renamed from `evalFrozenMeals` same sprint)** — the 12th category, for frozen/microwavable ready meals: unopened must be in the freezer, opened must be in the fridge (not freezer, not pantry) and then behaves like a 3-day leftover. Every existing `warn(...)` message across the file was also rewritten this sprint to name the specific correct storage location, since these messages are now what blocks a save (see `checkStorageSafety` above) rather than just labelling an allowed-through item

### `itemStatus.ts` (`src/lib/`)
- `computeStatusInfo(item)` — combines `getAdjustedExpiry` + `getDaysRemaining`/`getExpiryStatus` into one `{ result, badgeStatus, daysRemaining, countdownValue, countdownLabel }`, where `badgeStatus` is `'fresh' | 'soon' | 'expired' | 'warning'`
- Extracted from `ItemList.tsx` in Slice 5 so `useExpiryNotifications` uses the identical status logic rather than a second copy
- `daysRemaining` (signed, added Feedback Sprint real-UI-build 21/8/26) is distinct from `countdownValue` (`Math.abs(daysRemaining)`, used for display) — needed wherever the sign itself matters: urgency-sorting, and the list-view table's compact "3d left"/"2d ago" labels
- **`weeksNote(absDays, abbreviated?)` (Feedback Sprint 4, 24/8/26)** — once a countdown reaches a full 7 days, returns a `" (2 weeks)"` parenthetical (or `" (2w)"` with `abbreviated: true`); below 7 days returns `''`, unchanged. Folded directly into `countdownLabel` inside `computeStatusInfo`, so every existing caller of that field (the item card/detail-modal's big countdown via `CardHero`, `AttentionPanel`'s rows) picked up the addition automatically with no changes of their own; `ItemList.tsx`'s compact table column calls it separately with `abbreviated: true` for its own terser format

### `Donut.tsx` (`src/components/`) — added Feedback Sprint real-UI-build (21/8/26); given a real centre hole in the reference-matched redesign (21/8/26); rebuilt as a real SVG ring in UI feedback pass four (21/8/26)
- A real `<svg>` ring — one `<motion.circle>` per segment (`stroke-dasharray`/`stroke-dashoffset`, `stroke-linecap="round"` for rounded data-ends, a small length trim between segments so the card's own background shows through as a real gap) — replacing the earlier CSS `conic-gradient` disc, which had no way to gap or round segments. Segments sweep in on mount with a small stagger. An always-visible text legend (swatch + label + count per segment) sits beside the ring
- `holeSize` (60% of the outer diameter) punches a same-surface-colour circle out of the middle, showing the segment total (`holeUnit` prop, default `"items"`) by default. Hovering a segment (or its linked legend row — the two share one `hovered` key) thickens that segment and crossfades the centre to that segment's own count/label instead (`AnimatePresence mode="wait"`, `.donut-hole-inner`); a `.donut-legend-row-active` class highlights the matching legend row

- **Optional `activeKey?: string | null` prop (Feedback Sprint 3, 23/8/26)** — the reverse direction of the above: highlights the ring/legend/centre-swap to match whichever stat tile is currently selected, not just whatever's being hovered. A live hover still wins (merged as `hovered ?? activeKey`), so hovering never looks "stuck" on a stale click; once the mouse leaves, the selected tile's own slice stays highlighted instead of the ring going back to its plain total. `Dashboard.tsx` passes `activeKey={selected === 'all' ? null : selected}`
